# 商品效期提醒 App（Flutter）

> 使用說明與 APK 下載頁：https://snow30093.github.io/expiry-app/

## 開發環境需求
- Flutter SDK（Dart `>=3.3.0 <4.0.0`）
- JDK 17
- Android SDK `compileSdk 36`（`minSdk 24` 以上）

## 建置與測試
已是完整 Flutter 專案（含 `android/`、`ios/`），Android 設定皆已完成：
```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release --split-per-abi
```
編譯完成的 64 位元 APK 位於 `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`。

> **正式簽章設定**：目前若未提供 `android/key.properties`，`release` 版會自動退回使用 debug 金鑰（適合個人安裝測試）；若要正式簽署發佈，請將 `android/key.properties.example` 複製為 `android/key.properties` 並填入 keystore 資訊（該檔案與 `*.jks` 已列入 `.gitignore`，不會提交至 Git）。

## Android 設定（已完成）
- `android/app/build.gradle.kts`：`compileSdk` 至少 36、`minSdk` 至少 23、開啟 core library desugaring（`desugar_jdk_libs:2.1.4`）、自動偵測 `android/key.properties` 簽章
- `AndroidManifest.xml`：`CAMERA`、`POST_NOTIFICATIONS`、`RECEIVE_BOOT_COMPLETED` 權限；排程通知與開機後重新排程的 receiver；`android:allowBackup="false"` 保護本機資料庫；App 名稱「效期提醒」

## iOS 設定（已完成）
`ios/Runner/Info.plist` 已加入 `NSCameraUsageDescription`。

## 介面（A 單手作業版）
- 主題色：粉紅 `#E4007F`（`lib/main.dart` 的 `kPink` / `appTheme()`），只用在標題列、主要按鈕、選取狀態
- 狀態色：紅＝即將過期、橘＝待登錄、綠＝正常、紫＝已過期、灰＝已處理，並一律搭配文字
- 「掃描條碼」是畫面下方的全寬大按鈕；匯入、匯出收在右上角「⋮」選單
- 狀態按鈕上直接顯示數量；部門、排序改成下拉選單
- 卡片左側用大字顯示剩餘天數；右側「⋮」或長按卡片可標記已處理、刪除
- 登錄畫面：日期按鈕放大，儲存鈕放在下方

## 效期規則
- 一般部門：到期前 6 個月起標成「即將過期」
- 指定短效期部門（見 `lib/db.dart` 的 `kShortDepts`、`kShortDays`）：剩不到 45 天（44 天以下）才標成「即將過期」
- 提醒日當天早上 9:00 發一則彙總通知（例如「某商品 等 12 項商品進入即將過期」）；登錄時已在提醒範圍內則立即通知
- 通知只排接下來的 60 個提醒日，每次開啟 App 或資料變動時重排（避免超過 Android 每個 App 約 500 個排程的上限）
- 同一商品只保留一筆：再次掃描登錄時，新的到期日會取代舊的

## 掃描
- 只辨識一維商品條碼（EAN-13/8、UPC-A/E、Code 128/39/93、Codabar、ITF-14），QR Code 等二維條碼一律忽略（`lib/scan_page.dart` 的 `kLinearFormats`）
- 掃到的號碼同時比對「條碼」與「店內碼」，依序：條碼完全相同 → 店內碼完全相同 → 條碼忽略開頭的 0 → 店內碼忽略開頭的 0（UPC-A 匯出時常掉了開頭的 0）
- 少數商品共用同一個店內碼時，會列出來讓使用者選擇

## 國碼
- 畫面上原本的「條碼」欄位改叫「國碼」；匯出檔的表頭也是「國碼」
- 匯入檔的表頭寫「國碼」或「條碼」都可以
- 「掃描條碼」按鈕名稱不變（指掃描包裝上的條碼）

## 新增與編輯商品（`lib/product_form_page.dart`）
- 掃描到商品檔沒有的國碼時，會跳出視窗詢問是否新增；新增時掃到的條碼會先帶入「國碼」欄位
- 按「取消」後，同一個條碼 3 秒內不再跳出視窗（避免鏡頭還對著條碼一直跳）
- 長按已登錄的卡片（或按卡片右邊的「⋮」）→「編輯」：可改品名、部門、國碼、店內碼、到期日
- 新增與編輯共用同一個表單：除了店內碼，其他欄位都必填；部門用下拉選單
- 到期日可直接打字（2027/3/15、2027-03-15、20270315、民國 116/3/15），或按欄位旁的月曆圖案選
- 編輯時只改品名、店內碼或國碼，原本的紀錄（含「已處理」）保留；改了部門或到期日則重新登錄，重新計算提醒日與狀態
- 改國碼時，效期紀錄會一起改到新國碼；新國碼已被其他商品使用時會擋下

## 搜尋
- 主畫面統計下方的搜尋欄，輸入幾個字即可，比對品名、店內碼、條碼中任一處
- 用空白隔開多個關鍵字時，每個都要符合（例如「蜂蜜 卸妝」）
- 搜尋範圍是全部商品（已登錄與待登錄），可搭配部門篩選；搜尋時狀態分頁暫時隱藏
- 點結果可直接登錄或更新到期日；已登錄的長按可標記已處理或刪除

## 待登錄
- 還沒登錄過到期日的商品（匯入時有效日期是 0 或空白），會出現在「待登錄」分頁（「未處理」不變）
- 點清單上的商品或用相機掃描都可以登錄到期日；登錄後就移出待登錄，依日期歸到「即將過期」或「正常」
- 把那筆紀錄刪除後，商品會回到待登錄
- 商品可能有幾萬筆，清單每次載入 300 筆，可再按「再載入」

## 匯入
- 支援 .csv（UTF-8、Big5）、.xlsx、.xls（Excel 97-2003），依檔案內容自動判斷格式（`lib/file_io.dart`）
- 有效日期不是 0 的商品，匯入時直接登錄成到期日
- 商品已經有登錄的到期日時，保留原本日期，不會被檔案覆蓋；參考有效日期不是 0 也不覆蓋
- 品名、部門、店內碼照檔案更新

## 匯出
- 主畫面右上角「匯出」，可選 .xlsx（建議）或 .csv，再選存放位置
- 內容是全部商品，欄位同匯入檔：國碼、部門、店內碼、品名、有效日期
- 有登錄到期日的填登錄的日期，沒有的填 0；匯出的檔案可直接匯入另一支手機
- .xlsx 全部存成文字，條碼不會變成科學記號或掉了開頭的 0
- 不能匯出 .xls：沒有可用的套件能寫入舊版 Excel 格式（只能讀）

## 檔案格式
第一行為欄位名稱（Excel 檔可在前 10 行內），需含：部門、品名、國碼（或條碼）、店內碼、有效日期（順序不限，其他欄位忽略）。可參考 `examples/sample_products.csv` 進行測試匯入。
- CSV 支援 UTF-8 與 Big5
- 日期支援 2026-01-31、2026/1/31、20260131、民國 115/1/31
- 同一個條碼出現多次時以最後一行為準，並列在提醒中
- 用 Excel 存檔前請把條碼欄設成「文字」，否則會變成科學記號（例如 4.71E+12），這些列會匯入失敗
